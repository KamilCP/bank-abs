# Стандарт інтерфейсу користувача Bank ABS

Версія 1.0. Стандарт описує єдині правила побудови екранних форм веб-застосунку Bank ABS.
За основу взято підходи інтерфейсів автоматизованих банківських систем і систем класу «back-office»
(чітка навігація за модулями, табличні форми з фільтрами, двокрокове підтвердження фінансових операцій,
друковані квитанції), дизайн-систему Bootstrap 5 і рекомендації Microsoft Fluent і GOV.UK Design System
щодо форм і повідомлень про помилки.

## 1. Принципи

1. **Одна дія — одна форма.** Кожна сторінка вирішує одну задачу працівника (переказ, видача кредиту, журнал).
2. **Видно лише доступне.** Меню і кнопки показуються тільки для функцій, на які роль має право.
3. **Фінансова операція — з підтвердженням.** Спочатку розрахунок («Розрахувати»), потім виконання
   з діалогом підтвердження; після виконання — квитанція.
4. **Зрозумілі повідомлення.** Текст помилки пояснює, що сталося і що робити, без технічних кодів.
5. **Стан у адресі.** Пошук, фільтри, сортування і сторінка таблиці зберігаються в рядку адреси.

## 2. Структура екрана

```
┌──────────────────────────────────────────────────────────────────────────────┐
│ [логотип] Bank ABS │ Відділення № 1   12.11.2026  (?)  ПІБ / роль   [Вийти]  │ ← верхня панель
├───────────────┬──────────────────────────────────────────────────────────────┤
│ Головна       │ [значок] Назва сторінки                     [Дія] [Дія]      │ ← заголовок
│ КЛІЄНТИ І     │          підзаголовок / «хлібні крихти»                      │
│ РАХУНКИ       │ ┌──────────────────────────────────────────────────────────┐ │
│  Клієнти      │ │ повідомлення (успіх / помилки)                           │ │
│  Рахунки      │ ├──────────────────────────────────────────────────────────┤ │
│ ОПЕРАЦІЇ      │ │ панель: фільтри / форма / таблиця / діаграма             │ │
│  ...          │ └──────────────────────────────────────────────────────────┘ │
├───────────────┴──────────────────────────────────────────────────────────────┤
│ PostgreSQL · Користувач: admin                    Bank ABS 0.2.0 · збірка 15 │ ← рядок стану
└──────────────────────────────────────────────────────────────────────────────┘
```

* **Верхня панель** (темно-синя): назва системи, відділення, поточна дата, довідка, користувач і роль, вихід.
* **Бічне меню** згруповане за модулями: Клієнти і рахунки, Операції, Продукти, Звіти і аналіз,
  Довідники, Адміністрування, Допомога. Активний пункт виділяється синім.
* **Заголовок сторінки**: значок модуля, назва (h1), підзаголовок; кнопки дій — праворуч.
* **Рядок стану**: сервер БД, користувач, версія і номер збірки.

## 4. Шрифти і формати даних

* Шрифт — системний шрифт Bootstrap; цифри — табличні (однакової ширини) для вирівнювання сум.
* Номери рахунків — моноширинним шрифтом групами по 4 символи: `UA21 3990 0100 0002 6200 0000 1001`.

| Дані | Формат | Приклад |
|---|---|---|
| Сума | 2 знаки, пробіл між розрядами, кома, код валюти | `12 345,67 UAH` |
| Сума в діаграмах | скорочено | `1,2 млн` |
| Ставка | 2 знаки + «%» | `13,50 %` |
| Дата | ДД.ММ.РРРР | `12.11.2026` |
| Дата і час | ДД.ММ.РРРР ГГ:ХХ, часовий пояс банку (Київ) | `12.11.2026 14:05` |
| Курс | до 6 знаків | `0,023621` |

## 6. Табличні форми

* Над таблицею — **панель фільтрів**: поле пошуку (Enter або «Знайти»), списки фільтрів
  (застосовуються одразу після вибору), період (дати «з» і «по»), кнопка «Скинути».
* Заголовки колонок — великими літерами дрібним шрифтом; колонки, за якими можна сортувати, мають значок
  ↕; перше натискання — за зростанням, друге — за спаданням.
* Суми і кількості — вирівнювання праворуч; підсумки — у рядку `tfoot` на сірому фоні.
* Стан запису — позначкою (badge) з кольором і значком (п. 3).
* Назва або номер запису є посиланням на його картку.
* Під таблицею — «Показано 1–15 з 120» і кнопки сторінок; кількість рядків задає параметр `ui.page_size`.

## 7. Форми введення

* Підпис — над полем; обов'язкові поля позначаються червоною `*`; підказка — дрібним сірим текстом під полем.
* Тип поля відповідає даним: дата — `date`, сума — `number` з кроком 0,01, рахунок — поле з автопідказкою
  зі списку (номер і клієнт).
* Помилки перевірки показуються **у верхній частині форми одним блоком**, введені дані зберігаються.
* Кнопки внизу ліворуч: основна дія (синя), допоміжна (контурна), «Скасувати» (сіра).
* Небезпечні дії (блокування, закриття, розірвання) — червоні контурні кнопки з діалогом підтвердження.
* Фінансові операції: «Розрахувати» → блок попереднього розрахунку → «Виконати» з підтвердженням →
  квитанція з кнопкою друку.
* Після успішного збереження — перехід на картку запису з зеленим повідомленням (Post/Redirect/Get).

## 8. Звіти для друку

* Формат A4; меню, кнопки і фільтри на друк не виводяться (`@media print`).
* Шапка: назва банку і відділення ліворуч, дата формування і користувач праворуч, назва звіту великими
  літерами по центру, параметри (період, рахунок) під назвою.
* Таблиці з рамками, підсумки, місце для підписів відповідальних осіб.

## 9. Доступність

* Кожне поле має підпис (`label`) або `aria-label`; таблиці мають заголовки колонок.
* Контраст тексту — не нижче 4,5:1; стани не передаються лише кольором.
* Усі дії доступні з клавіатури; після переходу фокус встановлюється на заголовок сторінки.

## 10. Приклади екранних форм

| Тип форми | Приклад у програмі |
|---|---|
| Головна сторінка (панель показників) | `/` — показники, діаграма операцій, найближчі платежі, останні операції |
| Таблична форма | `/clients`, `/accounts`, `/operations`, `/admin/log` |
| Картка запису | `/clients/{id}`, `/credits/{id}` |
| Форма введення | `/clients/new`, `/admin/users/new` |
| Форма фінансової операції | `/operations/transfer`, `/credits/new` |
| Звіт для друку | `/reports/statement`, `/reports/daily` |
| Аналітична форма | `/stats` |

Знімки екранних форм наведено у звіті до лабораторної роботи № 4.
